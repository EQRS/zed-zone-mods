# ModConfig Panel 接入指南

> **开源地址**：https://github.com/EQRS/zed-zone-mods/tree/main/mods/ModConfigPanel

> 给 ZED ZONE 代码模组作者。看完这篇，你的模组就能有游戏内配置面板。

---

## 一分钟上手

**你什么都不用做。**

只要你的模组用 BepInEx 的 `Config.Bind()` 写配置，玩家装了这个面板就能看到：

```
BepInEx\config\<你的GUID>.cfg
```

面板会自动解析出所有配置项，包括类型（开关/数字）、默认值、取值范围、注释说明。

**这叫「零配置接入」，适用于 90% 的模组。**

---

## 三种接入方式

| 方式 | 适合 | 要做什么 | 能显示什么 |
|---|---|---|---|
| **零配置** | 大多数模组 | 什么都不用做 | 英文键名 + 注释 + 自动控件 |
| **JSON 声明** | 想要中文名、按钮 | 写一份 `modconfig.json` | 自定义显示名、按钮、布局 |
| **SDK 代码** | 需要动态生成 | 调 `ModConfigApi.Register()` | 完全控制 |

三种方式可以叠加：零配置打底，JSON 补中文名，SDK 处理动态部分。

---

## 方式二：JSON 声明

在你的模组目录下新建 `modconfig.json`：

```
<游戏目录>\Mods\你的模组名\modconfig.json
```

内容示例：

```json
{
  "schemaVersion": 1,
  "modGuid": "yourname.yourmod",
  "displayName": "你的模组名",
  "description": "一句话介绍",
  "configFile": "BepInEx/config/yourname.yourmod.cfg",
  "restartRequired": true,
  "groups": [
    {
      "section": "General",
      "title": "常规",
      "items": [
        { "key": "Enabled", "label": "启用", "type": "toggle", "default": true,
          "description": "关闭后模组完全不生效" },
        { "key": "Scale", "label": "倍率", "type": "slider",
          "min": 0, "max": 10, "step": 0.1, "default": 1, "unit": "x" },
        { "key": "restart", "label": "重启游戏", "type": "button",
          "action": "builtin:restart_game", "confirm": "确定重启吗？" }
      ]
    }
  ]
}
```

**重要**：JSON 是**增量合并**，不是替换。

你在 JSON 里没提到的配置项**不会消失**，它们会以自动解析的形式继续显示。
这样你可以逐步完善：先写最常用的几项中文名，其余留给自动解析。

---

## 控件类型速查

| type | 显示成 | 必填字段 |
|---|---|---|
| `slider` | 可拖动的滑条 | `min` `max`，可选 `step` `default` `unit` |
| `number` | 数字框 + 加减按钮 | 可选 `min` `max` `integer` `default` |
| `toggle` | 开/关开关 | 可选 `default` |
| `input` | 文本输入框 | — |
| `keybind` | 按键选择器 | — |
| `button` | 可点击按钮 | `action`，可选 `confirm` `params` |
| `text` | 只读说明文字 | `content` |

---

## 按钮动作

### 内置动作（`builtin:`）

| 动作 | 参数 | 作用 |
|---|---|---|
| `builtin:restart_game` | — | 重启游戏 |
| `builtin:open_folder` | `{"path":"..."}` | 打开目录（留空则打开 BepInEx） |
| `builtin:open_url` | `{"url":"https://..."}` | 打开链接（仅限 http/https） |
| `builtin:reset_section` | — | 把本组恢复默认值 |
| `builtin:show_log` | — | 打开 BepInEx 日志目录 |

### 自定义回调（`callback:`）

```json
{ "action": "callback:YourNamespace.YourClass.YourMethod" }
```

平台会反射调用你指定的方法。**约束**：

- 必须是 `public static void` 且**无参数**
- 必须在你自己的模组程序集内（白名单校验）
- 不允许调用游戏本体、BepInEx、UnityEngine、平台自身的程序集
- 调用失败只记日志，不影响游戏

## 方式三：SDK 代码

如果配置项是动态生成的，用代码注册更合适。

**你不需要引用 ModConfigPanel.dll**，通过反射软调用即可：

```csharp
// 找到平台（找不到说明玩家没装，静默跳过）
Type apiType = null;
foreach (var asm in AppDomain.CurrentDomain.GetAssemblies())
{
    apiType = asm.GetType("ModConfigPanel.Api.ModConfigApi");
    if (apiType != null) break;
}
if (apiType == null) return;   // 平台未安装

// 构造声明
// ... 详见 ModConfigBridge.cs
```

我们把整套反射调用封装在了 `ModConfigBridge.cs` 单文件里，**直接拖进你的项目就能用**。

## 让 AI 帮你生成

1. 把 `schema.json` 和你的 cfg 文件提供给 AI
2. 附上这段提示词：

```text
我有一个 ZED ZONE 的 BepInEx 代码模组，GUID 是 <你的GUID>，
配置文件在 BepInEx\config\<你的GUID>.cfg。
请参考附带的 schema.json 规范，为我生成一份 modconfig.json：
- 读取我的 cfg 里的所有配置项
- 给每个键起一个中文短名
- 布尔项用 toggle，数值项用 slider（范围参考 cfg 里的 Acceptable value range）
- 在最后一个组加一个「重启游戏」按钮，action 用 builtin:restart_game
```

3. 把 AI 生成的 JSON 放到模组目录即可。

## 常见问题

**Q: 我的模组没出现在面板里？**
A: 打开面板点「诊断」，会显示解析失败的原因。

**Q: 中文显示成方块？**
A: 不会，平台用的是游戏自带字体。

**Q: 改了配置要重启吗？**
A: 由 `restartRequired` 决定（默认 true）。保存时会提示。

**Q: 我的声明写错了会影响游戏吗？**
A: 不会。平台对每个模组独立容错，出错的只跳过它自己。

**Q: 平台没装时我的模组会崩吗？**
A: 不会。软调用找不到 API 时静默跳过。

## 附：关于游戏根目录定位

平台会自动检测游戏根目录，支持 6 种策略：

| # | 策略 | 适用场景 |
|---|---|---|
| 1 | 从 DLL 位置向上找 `ZEDZONE.exe` | 装在 `Mods\` |
| 2 | 从 `steamapps` 路径反推 | **订阅工坊**（DLL 在工坊目录） |
| 3 | 读 `BepInEx.Paths` | 通用兜底 |
| 4 | 读注册表 Steam 库 + appmanifest | 游戏不装在默认位置 |
| 5 | 读当前进程路径 | 极端兜底 |
| 6 | 读工作目录 | 极端兜底 |

**注意**：工坊物品里的 DLL 是**原地加载**的（不在 `Mods\`），
所以策略 1 会失败，必须靠策略 2。这也是 v1.0.0 的 bug 所在，v1.0.1 已修复。

如果全部失败，可以在 `BepInEx\config\zedzone.modconfigpanel.cfg` 里手动指定：

```ini
[General]
GameRootOverride = D:\Steam\steamapps\common\ZED ZONE
```

写错路径不会崩溃，会自动回退到自动检测。
